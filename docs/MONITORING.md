# TRIADA: щоденний моніторинг

Узгоджено 29 жовтня 2026 року: спочатку безкоштовні джерела; один пошук
на добу; пріоритет Facebook, Instagram, X, YouTube. Сторонні згадки про
TRIADA та її продукти; власні публікації не включаємо автоматично.
Виняток — нові статті Артема Веселова на Мілітарному від 29.10.2026.
Історичні 311 перевірених записів залишаються без змін.

## Цикл

GitHub Actions щодня о 07:00 UTC запускає тести, пошук, перевірку,
збереження бази та публікацію сайту. Час старту може затримуватися GitHub.
Library й Overview будуються з однакового набору дозволених записів.
Нові записи змінюють загальну кількість, платформу, частки, графік та топ джерел.
Відкрита сторінка отримує нову базу після перезавантаження; лічильник днів
оновлюється окремо без перезавантаження.

## Джерела і межі покриття

| Канал | Реалізація | Межа |
|---|---|---|
| Google News | 21 запит, українська й англійська регіональні видачі | Лише проіндексовані матеріали; старий пошук починається з червня 2026 |
| Bing | Загальні запити та окремі site-запити для кожної соцмережі | Це вебіндекс, а не внутрішній пошук платформ |
| RSS / API медіа | Мілітарний UA/EN, dev.ua, ITC.ua, Euromaidan Press, РБК, UNITED24; Defender через публічний WordPress API | Стрічки мають обмежену історію; не всі відповідають |
| GDELT | Новинний індекс | Можливі 429; для публікації потрібні сторінка й дата видавця |
| Facebook, Instagram, X, LinkedIn, Telegram | Пошук індексованих публічних дописів через Bing | Не бачить приватних постів, усіх коментарів чи всіх дописів; сторінка може вимагати входу |
| YouTube без ключа | Публічний вебпошук | Неповне покриття |
| YouTube API | Готовий адаптер, увімкнеться за наявності YOUTUBE_API_KEY | Пошук і перевірка назви/опису; не транскрипція відео, не коментарі |
| Google Alerts | Наявний адаптер; потрібні RSS-адреси в GOOGLE_ALERTS_RSS | Поки не налаштовано |
| Артем на Мілітарному | Авторський RSS та сторінка автора, перевірка авторства й дати | Лише нові статті; до 20 посилань зі сторінки автора |

Довгі тексти RSS (від 1000 символів) перевіряються без повторного завантаження
статті; для коротких описів збирач також відкриває оригінал. Обрізані стрічки
та неповний вебіндекс можуть залишати пропуски.

Під час живої перевірки Bing ігнорував site-фільтр у багатьох запитах.
Такі запуски позначаються partial через query_scope_violations, а сторонні
результати відсіюються. Це налаштований допоміжний пошук, не надійне
самодостатнє покриття Facebook/Instagram/X.

Новий пошук соцмереж: 6 запитів × 7 доменів = 42 запити на добу.
X і twitter.com належать до однієї платформи. Перевіряється до 25 нових
унікальних дописів на платформу за запуск; досягнення межі видно у звіті.
YouTube API: до 2 сторінок по 50 результатів для кожного з 6 запитів,
потім videos.list для повних описів. Це обмежений щоденний пошук, не гарантія
вичерпного історичного архіву. Платні API та сервіси не підключено.

## Правила публікації

- Пошуковий заголовок чи фрагмент сам по собі не є підтвердженням.
- Для соціального допису потрібні дані саме цього поста з оригінальної
  платформи: текст із релевантною згадкою, автор і справжня дата публікації.
- Автоматичне підтвердження вебсоціальних результатів консервативне:
  потрібні структуровані SocialMediaPosting/VideoObject дані з URL, що збігається.
  Якщо платформа не віддає їх, запис лишається на перевірку.
- YouTube API підтверджує згадку в назві/описі. Це не доказ згадки в аудіодоріжці.
- Домени визначають платформу: допис Facebook не стає Media.
- URL власної сторінки/автора виключає новий власний допис. Невідомі
  альтернативні назви власних сторінок потрібно додавати до конфігурації.
- Для нових результатів Bing/GDELT не підставляється день знаходження
  замість відсутньої дати виходу. Такі результати чекають перевірки.
- Різні пости з однаковим текстом зберігаються окремо; повтор того самого
  URL не повинен додавати новий запис.
- Історичні ручні дані, виключення та рішення щодо дублікатів зберігаються.
- Не здійснюються оцінка тональності, аналіз зображень/відео чи підрахунок охоплення.

## Контроль результату

`collector_status.json` містить стан кожного медіаконектора та
`channel_monitoring`: запити кожної соціальної платформи, кількість
результатів і посилань на дописи, підтверджені/відкладені записи, помилки
й досягнуті ліміти. `ok` означає технічно успішний запит, а не повне покриття.

`mentions_review.json` — кандидати; не всі вони показуються на сайті.
`mentions_flags.json` — можливі дублікати та спільні посилання.
`tracker/build_report.json` на сайті — кількість реально показаних записів.
Інтерфейсу модерації поки немає; перевірку виконує супроводжувач через файли.

## Потрібні дії власника

1. Створити Google Cloud-проєкт, увімкнути YouTube Data API v3, створити
   API-ключ з обмеженням на цей API та додати його як GitHub Actions secret
   `YOUTUBE_API_KEY` у staging. Не зберігати ключ у коді чи чаті.
2. Для Google Alerts створити сповіщення за ключовими назвами з доставкою RSS;
   зберегти адреси, кожну з нового рядка, у `GOOGLE_ALERTS_RSS`.
3. Повідомити додаткові власні акаунти/канали, якщо вони з'являться.

Повний пошук по всіх дописах Meta/X цим безкоштовним контуром не обіцяється.
Після перевірки фактичних пропусків можна окремо погодити платне покриття.
